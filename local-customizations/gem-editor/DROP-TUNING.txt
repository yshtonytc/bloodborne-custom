宝石掉落调校（2026-10-27）

入口：启动器 → 模组与补丁 → 配置宝石掉落。
输出 MOD：安装目录 mods/GemDropTuning。
默认开启已识别来源的最高生成档，37 类词条的权重均为原版 1 倍。
勾选开关、修改相对倍率后，点击“生成并启用”，下次启动游戏生效。
要恢复原版掉落，在模组列表取消 GemDropTuning；不用恢复存档或原游戏文件。

当前来源满 roll 的实现边界：
- 仅把 39 个已识别主线／圣杯 GemDropDopingParam 的 rankMin 固定到原 rankMax。
- 不提高原 rankMax，不增加 GemGenParam 的生成器加成，不修改任何 SpEffect、
  Gemeffect、GemGen、形状、掉落数量或词条槽数。
- 原先固定档位和通用 1～100 来源、99... 测试来源均不动。
- 这是“来源最高生成档”的参数实现。内部档位不等于界面显示评级；
  未经实际掉落实测，不能据此承诺所有副词条数值都已满 roll。
- 负面效果没有直接改成最差数值；同一来源最高档可能按原版曲线影响诅咒强度。

权重：
- 只调整存在且能唯一归类的血宝石叶类别的 ManifestRate，相对原版重新计算。
- 1=原版，0.1=原权重的十分之一，2=两倍。这不是固定出现百分比，
  候选池、地牢类型、亲和关系、排斥关系和固定词条仍按原版规则。
- 允许 0.01～10，禁止 0/负数/NaN，避免制造空候选池。
- 原本零权重的类别不激活；符文类别、混合/未知类别及父类别不改。
- 每次从原参数重建，不叠乘上一次结果。编辑 JSON 后也要重新生成。

命令行：
  .\build-gem-drops.cmd
  .\build-gem-drops.cmd --config <JSON路径>
  .\build-gem-drops.cmd --out <输出目录>  （只构建，不安装、不改开关）
配置文件：mods/GemDropTuning/settings.json（schema/max_roll/weights）。
JSON 词条键为英文内部键；启动器显示中文，不要求手动编写 JSON。
命令行只管理模组选择，加载模组总开关由启动器管理；GUI“生成并启用”会开启总开关。

与血岩共存：
- 参数包以已校验的血岩 MOD 为基底，保留其额外 ItemLot，不包含地牢事件文件。
- 血岩的事件仍由 ChaliceClearBloodRock 自己的勾选状态控制。
- 安装时血岩原本关闭，仍保持关闭；启用新的宝石 MOD 不会额外奖励血岩。
- 两者都启用时，GemDropTuning 要排在血岩后面；加载器会检查顺序、文件哈希
  和血岩参数版本。发现其他参数包冲突或过期基底时拒绝该覆盖层并提示合并。
- 调校包请求隔离旧模拟器覆盖层，不加载原游戏旁边陈旧的 legacy MOD。

构建直接修改原 PARAM 的指定字段字节，不重序列化整个参数表，保留重复行 ID、
未修改行、名字表和其他 BND 成员；完整重读校验后才发布新 MOD。
构建暂存目录放在 user 下，不能放在 mods 下被启动中的扫描误识别。
运行中拒绝生成；共享存档恢复锁防止本工具并发操作；发布失败恢复上一份 MOD。
它不读取或修改已有宝石存档。

验证：9 项自动测试、隔离目录中的打包 GUI + 真实构建器测试通过。
实际覆盖加载分别验证了血岩开/关两种情况、调校参数哈希及事件层选择。
新存档编辑器窗口和更新器回归通过。6,851 个原受保护文件保持不变，
有意修改的仅为 mods.json 新选择及启动器 mods_enabled 总开关。
尚未打怪实测掉落数值或统计词条频率，不把静态参数检查当实战证明。
报告在 mod-work/gem-drops/；已安装 MOD 的 validation.json 记录实际改动。
